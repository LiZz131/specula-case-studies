这些行读或写任期、日志、提交点、快照点。不是防御性返回，守卫可以写成 spec 变量上的谓词，也不是初始化或销毁。

### 加载快照

`raft_begin_load_snapshot`、`raft_end_load_snapshot`、`log_load_from_snapshot` 调用次数都是 0。成功路径包括 `raft_server.c:1383` 的 `current_term = last_included_term`（KB-1 那次赋值），以及随后清空日志、抬提交点、改 `last_applied`。对应模型动作是 `HandleInstallSnapshot`。

- `raft_server.c`：`raft_voting_change_is_in_progress`、`raft_add_non_voting_node`、`raft_add_non_voting_node_internal`、`raft_remove_node`
- `raft_node.c`：`raft_node_set_voting`、`raft_node_has_sufficient_logs`、`raft_node_set_has_sufficient_logs`、`raft_node_is_voting_committed`、`raft_node_set_addition_committed`、`raft_node_is_addition_committed`

## 防御性分支，白名单

成功路径已经走过，剩下的是失败就返回、不改协议状态的行。守卫多半能写成谓词，但表达的是错误码、空指针或「不许删已提交条目」，不是还要去采样的协议步骤。与初始化无关。

包括：分配失败时的 `return NULL` / `RAFT_ERR_NOMEM`；`assert` 失败臂；已提交条目冲突时的 `RAFT_ERR_SHUTDOWN`（`raft_recv_appendentries` 约 442、462、492 行）；`raft_cancel_snapshot` 整段（快照进行中被取消；`begin`/`end` 已执行 371 次）；`raft_begin_load_snapshot` 里那些 `return -1`；`log_delete` 在下标非法或已经删到 base 时的返回。`log_delete` 本身调用了 4 次。

## 当前界限下守卫为假

有 spec 里能对上的量（日志长度、投票节点数），也能写成谓词，但这份配置让守卫恒假。不是成员变更，也不是销毁。

- `log.c` 的 `__ensurecapacity`（约 57–75 行）和 `log_get_from_idx` 的环绕拷贝（193 行）。初始环形缓冲装得下 `MaxLogLength = 4`，扩容和下标回绕走不到。

不要为了这两处去改 `MaxLogLength` 或服务器个数，除非单独开一份配置。它们不进入上面的 B 类下一步。
