# 未覆盖代码分类

第三轮六种配置各 100 条受控执行，变量比较全部通过，实现侧合计 1203.3 秒。下面按「有没有 spec 变量、是不是防御性代码、守卫能不能写成谓词、是不是只在初始化或销毁时运行」把仍然整段没执行的函数分开。测量来自投票配置跑完后的 gcov，再加上一条 80 步深轨迹。

## 已经补上的重要路径

轨迹在 `sandtable/build/mount/systems/WRaft-series/SpeculaWRaft/bugs/random/deep3/s001/`（`MC.out`、`traces.txt`、`log.host`）。

## B 类：还有 spec 变量，模型写了，采样没走到

`raft_delete_entry_from_idx`、`log_delete`、`raft_pop_log`。AppendEntries 在同一下标发现不同任期时删掉该下标及其后缀（`raft_server.c:467` 和 `:495`）。`SandHandleAppendEntriesRequest` 里的 `firstConflict` 就是这个守卫，可以写成 spec 变量上的谓词。投票配置加上上述深轨迹里这三个函数仍是 0 次。值集合只有 `v1`，冲突只能来自不同任期。现有界限下这条路径很少被抽到。

## 模型没有的场景，留给 Specula 重做

成员变更。`raft_add_non_voting_node`、`raft_remove_node`、`raft_voting_change_is_in_progress`、`raft_node_set_voting`、`raft_node_set_has_sufficient_logs`、`raft_node_*addition_committed*`。现有模型的 `Value` 只有普通条目 `v1`，没有配置变更条目，也没有非投票节点。这些函数读写的是节点表和投票权，不是现在这组 spec 变量。

## 防御性分支，可以放过

提前失败后返回，不改协议状态：

- `raft_cancel_snapshot`：快照进行中被取消
- `raft_begin_load_snapshot` 里 index 为 0、任期为 0、低于 `last_applied`、低于当前日志、或已经加载过。成功路径已经走过；这几个 `return -1` 仍是 `#####`
- `mod`：日志环形缓冲下标回绕，当前日志很短，走不到

低优先级。销毁路径留着，是因为释放函数里更容易藏资源泄漏，但这次没有崩溃和恢复动作。

- 销毁：`raft_free`、`log_free`、`raft_node_free`、`log_clear_entries`、`log_empty`、`raft_clear`
