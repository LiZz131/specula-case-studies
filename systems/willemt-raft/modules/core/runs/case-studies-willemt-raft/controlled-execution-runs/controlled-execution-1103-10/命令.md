# willemt/raft 受控执行命令

节点名来自模型里的 server。`s1`、`s2`、`s3` 对应实现节点 `n1`、`n2`、`n3`。发送顺序与驱动按名字把节点加入库的顺序相同，即 `s1`、`s2`、`s3`。

持久副本写在节点容器的 `/tmp/wraft-persist-n<编号>`。崩溃保留这份文件并释放进程内的 raft 对象。恢复只读这份文件，再让库自己初始化易失状态。

## 时间事件

库的 `request_timeout` 是 200 毫秒。`election_timeout` 是 1000 毫秒，实际阈值在 `[1000, 2000)` 之间。两个事件用不同的拨钟量。

| 动作 | 拨钟 | 调用 |
|---|---|---|
| Timeout | 2000 毫秒 | `raft periodic 2000` |
| BroadcastAppendEntries | 200 毫秒 | `raft periodic 200` |

## pc

| pc | 命令 |
|---|---|
| Init | `raft init`，然后等待连接。不调用无参数的 `periodic` |
| Timeout | 见上 |
| ClientRequest | `raft cli <值>` |
| BroadcastAppendEntries | 见上 |
| SendAppendEntries、SendInstallSnapshot | `raft sendto <对端>`。一次 `raft_send_appendentries` 返回 |
| TakeSnapshot | `raft snapshot` |
| Crash | `raft crash` |
| Recover | `raft recover` |
| LoseMessage | `drop-unordered <源> <目的> <seq>` |
| DuplicateMessage | `duplicate-unordered <源> <目的> <seq>` |
| Handle* | `deliver-unordered <源> <目的> <seq>`，再 `raft recvfrom` |
