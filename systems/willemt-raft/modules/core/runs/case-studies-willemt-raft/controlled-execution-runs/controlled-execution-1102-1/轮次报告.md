# controlled-execution-1102-1

willemt/raft。八个配置各 100 条轨迹。`base.tla` 的每个 action 都至少执行了一次，包括崩溃、恢复和装入快照。15 条变量不一致：11 条是实现和 Raft 协议冲突，4 条是规格和代码不一致、代码这一步并不违反协议。没有未归类的失败，没有 `adapter`，没有仍标成 `crash` 的行。

## 启动

节点 n1、n2、n3。控制器容器 `controller`。工作副本在 `/users/bingzhuo/sandtable/build/mount/specula-wraft`，容器里是 `/root/sandtable/specula-wraft`。控制器二进制用的是已经编好的 `/root/sandtable/cmake-build-debug/controller/controller`，这一轮没有重编控制器。

```text
python3 sandtable/scripts/run_round.py --phase all --configs all --seeds 1-100 --jobs 8 --fresh
python3 sandtable/scripts/run_round.py --phase replay --configs install-deep --seeds 1-100
```

## 失败

全表在 `failures.tsv`。按 Raft 的复制、快照和提交规则重新判过，不把 `base.tla` 当成协议。adapter 没有改这些状态：线上字节数和库实际发出的条目数一致，`log` 读的是库内存。

| 配置 | 轨迹 | 归类 | 变量 | 判定 |
|---|---|---|---|---|
| standard / vote | t0049、t0084 | spec | nextIndex | 规格把领导者自己也写进 `nextIndex`。协议不要求更新自己 |
| install-deep | t0020、t0033 | spec | log | `SubLog` 在 `nextIndex <= 快照` 时凭空带上后缀。库发的是空 AppendEntries，跟随者保持原日志是对的 |
| install-deep | t0014、t0030、t0036、t0037、t0038、t0051、t0060、t0073、t0083 | bug | log | 同一封消息，代码把已经在快照里的条目又追加到后缀。t0014、t0036、t0073、t0083 的模型日志也不是协议要求的长度 |
| install-deep | t0026、t0086 | bug | commitIndex | 空日志上 `max(current_idx, 1)` 然后断言退出。模型的 commit 来自 `SubLog` 多放进消息的条目 |

库在相等情况下不发 InstallSnapshot（`next_idx < snapshot_last_idx`），这违反协议，但 `base.tla` 用了同一个 `<`，又用 `SubLog` 补了一封代码没发的 AppendEntries。所以 t0020、t0033 的 compare 记成规格问题，发送缺陷写在 `log-crash/README.md`。

细节、复现命令和建议修改在三个 `potential-bugs/*/README.md`。库和 `spec/base.tla` 都没有改。受控的 `Crash` 和 `Recover` 成功时不在这张表里。
