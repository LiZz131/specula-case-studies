RedisRaft。100 条 depth-30 轨迹，外加 1 条快照装载见证。`base.tla` 的每个 action 都至少执行了一次，code 在每一步前后与模型变量一致。没有 `failures.tsv`。

## 启动

节点 n1、n2、n3，控制器容器 `controller`。工作副本在 `/users/bingzhuo/sandtable/build/mount/specula-ce`，容器里是 `/root/sandtable/specula-ce`。采样与回放：


覆盖率二进制是 `sandtable/driver/build/RedisRaftDriver`（`--coverage`，`SPECULA_COVERAGE`）。Sanitizer 是另一个二进制 `build-san/RedisRaftDriver`。

## 和规格对齐时偏离了生产的地方

`specula_step` 为 1 的整次 run 里，库不会在一个调用里把下一个规格动作做完。单节点即时提交、发送时推进 next、结束快照时发送、装入快照时删节点、提交移除时释放节点，都没有执行。这些不是这一轮发现的库 bug。`ClientNonQuorumRead` 不在 raft 库里，旗标是驱动按规格谓词写的。

`messages` 只做了 `compare net-len`。节点上的变量在每一步前后都和模型对过，并且控制器把 code 和 model 都打了出来。
